# ADR-009: 故事知识库快速分析逐批提交

## 状态

Accepted

Supersedes ADR-008 中“主动取消全额退款”的规则；保留其字数档位与预扣规则。

## 日期

2026-09-28

## 背景（Context）

原精细模式按约 1.2 万字符串行提取，再多层归并；长篇调用多且完成前没有可见结果。用户希望百万字小说尽量在数分钟分析，并优先减少模型费用。

## 问题（Problem）

整本一次调用可能超过模型上下文或输出容量；取消后需保留已完成内容且不退积分，模型最终失败则退积分。原先整本完成才写入的事务边界不满足逐批可见。

## 决策（Decision）

- 保留精细模式，快速模式默认；两者沿用相同的原文计费字数积分档位。
- 管理员为每个模型填写实测的上下文、可输入正文字符、输出容量、每批片段数和最多补分析调用次数。50 万字符仅为硬上限，不能从 1M Token 直接推算输入字数。
- 快速模式最多两批受控并行，逐批校验章节覆盖与原文引文，使用现有条目写入器和锁定条目保护。批次检查点与知识库条目在同一事务提交，取消与提交通过任务行锁互斥。
- 不完整批次拆小补分析，补分析次数耗尽则保存缺口并标记部分完成。主动取消不退积分，保留已提交结果；最终模型故障全额退款并保留已完成结果，显示不完整状态。
- 用户先用实际长篇与模型实测耗时、质量和真实费用；5 分钟与降费 50% 暂不作为上线门槛。

## 方案比较（Alternatives）

| 方案 | 优点 | 放弃原因 |
| --- | --- | --- |
| 整本一次调用 | 请求少 | 容量和结构化输出完整性无法保证 |
| 原精细模式提并发 | 改动小 | 调用次数和费用仍高 |
| 按容量切批并逐批提交 | 降低重复输入，取消时结果可用 | 需管理补分析和并发提交 |

## 原因（Rationale）

以管理员实测值约束输入，沿用原文证据与人工条目保护，并把提交边界缩小到批次，能在不猜测模型容量的情况下提供可见进度和受控成本。

## 影响（Consequences）

### 正面影响

- 已完成内容及时可见，取消后仍可查阅。
- 补分析只针对失败片段，调用次数有上限。

### 负面影响

- 大批输出仍可能遗漏细节，部分完成需要展示缺口。

### 风险

- 上下文、输出容量和费用因渠道而异，管理员配置必须经实测；实际费用下降幅度待验证。

## 后续行动（Action Items）

- 用百万字以上的真实小说测量耗时、引文有效率、覆盖情况和供应商费用，按结果调整容量与补分析次数。
