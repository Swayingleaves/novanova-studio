# ADR-014: 小说改编失败按成功草稿检查点续跑

## 状态

Accepted

## 日期

2026-10-01

## 背景（Context）

一键改编保存草稿、事实快照、阶段和调用进度，但失败后没有续跑入口，重新启动会删除待审草稿并重复生成前置内容。

## 问题（Problem）

需要保留正式内容和成功草稿，从缺失批次继续，避免重复生成、重复扣费和多次退款混淆。仅按全局进度跳过无法区分不同分集与事实批次，也可能在草稿保存后、进度更新前中断。

## 决策（Decision）

- 复用已保存改编草稿作为成功检查点，身份由阶段、目标分集和排序后的事实标识集合确定。
- 草稿、事实快照与任务归属在同一保存事务内提交；执行与续跑报价共用生成单元规划，成功批次不再调用模型。
- 最近失败任务刷新后仍展示，用户通过“从失败阶段继续”确认恢复；真实目标内容、事实版本或事实分批变化时明确拒绝续跑。
- 保留失败时的未结算退款规则；续跑按原单价对缺失内容重新报价预扣。使用持久化 `retry_count` 生成各次独立计费标识，重复请求不重复排队或扣费。
- 一键任务生成使用已预扣额度，单次改编仍按单次扣费。
- 失败状态与退款同一事务提交，续跑报价和后台恢复共用基线校验，同一停点生成使用固定修订号。

## 方案比较（Alternatives）

| 方案 | 优点 | 不采用或采用原因 |
| --- | --- | --- |
| 从头重新生成 | 实现简单 | 丢弃成功草稿，浪费模型调用并覆盖前置内容 |
| 按全局调用序号跳过 | 无需查询草稿 | 分批或分集变化后序号失真，保存与进度间有中断窗口 |
| 成功草稿作为检查点 | 复用已有事实快照，恢复依据直接可核对 | 采用；只新增计费尝试次数，无需复制生成数据 |

## 原因（Rationale）

成功产物是比进度计数更可靠的恢复依据。批次身份精确区分同一分集的多个事实批次，恢复不要求用户重做已确认阶段。

## 影响（Consequences）

### 正面影响

- 骨架、分集规划与正文均可从缺失批次继续。
- 保留用户审阅入口，成功内容不重复生成或收费。

### 负面影响

- 续跑报价需要读取任务草稿并核对事实与当前正式目标。

### 风险

- 模型输出本身仍可能不符合结构或引用约束，需要修复原因后由用户继续。
- 分批范围或正式内容发生变化时不能直接复用旧草稿，必须明确审阅处理。

## 后续行动（Action Items）

- 执行恢复规划、幂等计费与跳过成功草稿的回归用例。
- 验证长篇小说在正文失败、页面刷新与再次失败后的恢复流程。
