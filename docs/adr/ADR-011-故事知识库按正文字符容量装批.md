# ADR-011: 故事知识库按正文字符容量装批

## 状态

Accepted

Supersedes ADR-009 中“每批片段数限制”的决定。

## 日期

2026-09-28

## 背景（Context）

实际小说有 551 个章节片段、约 126 万正文字符。管理员配置单批 50 万字符，但每批最多 5 片使初始请求达到 111 批。

## 问题（Problem）

片段数量提前封批，导致大上下文模型的已配置输入容量无法使用，并增加调用次数和等待时间。

## 决策（Decision）

- 章节片段只用于原文定位和覆盖校验；按配置的单次正文字符上限聚合为模型请求，不再按片段数量封批。
- 单批字符硬上限仍为 50 万；模型上下文 Token 不直接换算为正文字符数，管理员填写经过验证的字符上限。
- 启动前显示初始批数；输出截断或结果不完整时，沿用既有拆批和补分析次数上限。

## 方案比较（Alternatives）

| 方案 | 优点 | 取舍 |
| --- | --- | --- |
| 保留片段数上限 | 单次输出较短 | 对短章节产生大量请求 |
| 按正文字符容量装批 | 减少初始调用 | 单批输出更长，可能触发拆批 |

## 原因（Rationale）

模型请求量应由已配置的输入容量决定；章节片段数量不代表输入容量。

## 影响（Consequences）

### 正面影响

- 短章节小说显著减少初始批数。

### 负面影响

- 单批结构化输出变长。

### 风险

- 模型可能因为输出长度或超时拆批；实际完成时间与调用次数需要实测。

## 后续行动（Action Items）

- 用长篇小说实测初始批数、输出完整性和补分析次数。
