# ADR-017: 开源版与企业版独立维护和部署

## 状态

Accepted。用户于 2026-10-12 要求两个项目完全独立，并明确 OSS 继续共用。

## 日期

2026-10-12

## 背景（Context）

两个项目已有独立 Git 仓库、开发端口、PostgreSQL 和 Redis 容器及数据目录，但 pnpm 依赖硬链接和缓存、Docker 应用镜像名称、构建缓存、生产 Nginx 宿主机网络与配置目录、应用密钥及企业版部署目录仍存在共享。

## 问题（Problem）

一个项目的依赖文件权限、镜像构建或部署不能影响另一个项目；两个服务不能相互接受登录凭据，也不能默认合并代码或数据库迁移。

## 决策（Decision）

- 两个仓库独立维护源码、迁移和 ADR。后续同步须由用户明确提出。
- pnpm 使用项目内的 web/.pnpm-store，并通过 packageImportMethod: copy 安装独立文件副本，关闭全局虚拟存储。
- Maven 使用项目内 server/.maven-repository；Docker 构建使用各项目专属的缓存标识。
- Compose 明确项目名称，分别使用自己的前后端镜像、容器、桥接网络、端口、Nginx 配置、数据目录和日志目录；企业版部署到 /data/novanova-studio-pro。
- 保留两个独立 PostgreSQL 实例、Redis 实例及现有业务数据，不移动或合并数据。数据库名称可以相同，因为实例不同。
- 两个项目分别维护 APP_SECRET_KEY。轮换企业版密钥前备份旧配置与密文，并使用现有 AES-GCM 格式重新加密已有敏感字段；不更改开源版密钥。
- OSS 按用户要求共用现有存储桶及配置，不复制、迁移或删除已有对象。
- 两个前端使用不同端口，使浏览器本地业务存储按来源隔离；企业版主题 Cookie 使用独立名称，因为 Cookie 不按端口隔离。

## 方案比较（Alternatives）

| 方案 | 优点 | 问题 |
| --- | --- | --- |
| 保留共享缓存、硬链接和应用镜像 | 节约磁盘与下载时间 | 文件权限和镜像标签可能跨项目产生影响 |
| 项目缓存与文件副本独立，运行环境独立 | 故障与变更范围清晰，可独立开发部署 | 增加磁盘占用与首次安装时间 |
| 全部外部服务也独立 | 隔离范围最大 | 与用户明确要求 OSS 共用不符 |

## 原因（Rationale）

采用第二种方案，使共享成为明确约定的例外。保留成熟工具，避免增加跨项目同步机制或旧数据兼容逻辑。

## 影响（Consequences）

### 正面影响

- 依赖文件权限、应用镜像构建、数据库迁移与缓存队列不会跨项目传播。
- 两个项目可以分别安装、构建、启动和部署。

### 负面影响

- 独立缓存和依赖副本增加磁盘使用量。
- 企业版密钥轮换后需重新登录。

### 风险

- 手工覆盖环境变量为另一个项目的连接地址会破坏隔离。
- OSS 共用意味着对象删除或存储桶策略调整仍可能影响两个项目，须按共享资源处理。
- 生产 Nginx 改为桥接网络和独立 HTTP 端口，外部域名与 HTTPS 入口需指向各自端口；本次不操作远端部署。

## 后续行动（Action Items）

- 安装后核对两个项目使用不同缓存目录，依赖文件无跨项目硬链接。
- 核对 Compose 渲染结果中的镜像、端口、网络和挂载目录独立。
- 保留密钥轮换的本地恢复备份，不纳入 Git。
- 按各项目自己的流程构建与部署，不自动同步另一版本。
