# ADR-002: 漫剧生产数据与共享剧本分离建模

## 状态

Accepted

## 日期

2026-09-21

## 背景（Context）

漫剧创作继承剧本创作的故事、人物、地点、分集、场次和正文，但还需要维护视觉资产版本、镜头、分镜、提示词、媒体结果、批量任务和上游变更影响。现有无限画布以 JSON 保存节点，适合自由编排，不适合作为需要稳定引用和生产状态查询的领域数据源。

## 问题（Problem）

需要在不复制 `script_project` 数据的前提下，保证人物、地点和场次等上游实体能够被镜头及生成结果稳定引用；同时上游修改只能标记下游需要更新，不能覆盖旧结果或静默触发计费任务。画布还需要继续作为可复用的视觉编排空间。

## 决策（Decision）

- 以 `script_project_id` 作为漫剧生产项目的唯一主线，在独立的 `comic_drama_*` 关系表中保存生产数据。
- 项目设置、视觉资产及版本、镜头草稿/正式镜头、提示词版本、媒体结果、更新影响、批量任务和画布绑定均与生产项目关联；正式镜头字段关系化，异构生成输入和快照使用 JSONB。
- 漫剧服务通过稳定的剧本实体 ID 读取共享剧本，不复制故事或正文；剧本替换式保存不使用会阻塞上游编辑的下游外键。
- 分镜拆分和提示词合成结果先保存为草稿，生成任务必须经过前端展示范围/费用并由用户确认后才提交；上游变化只写入影响标记，更新范围由用户确认。
- 无限画布继续保存自己的节点 JSON，通过绑定表与项目、资产或镜头建立可追踪关系。

## 方案比较（Alternatives）

### 直接复用画布分镜节点作为正式数据

实现速度快，但无法可靠查询项目级镜头、版本和引用关系，也无法在剧本替换保存后精确计算影响范围，因此未采用。

### 在 `script_projects` 中增加全部生产字段

可以减少表数量，但会把生产配置和媒体状态污染纯剧本工作区，且资产/镜头天然是一对多并需要独立历史版本，扩展和查询边界不清晰，因此未采用。

### 独立漫剧关系模型并绑定共享剧本

能够保持单一剧本数据源，按项目查询生产状态和引用关系，并保留旧版本与失败结果；代价是需要维护一层关联服务和迁移，因此采用。

## 原因（Rationale）

该方案同时满足“同一项目无复制”“下游结果可保留”“生产配置不进入剧本核心工作区”和“画布可复用”四项长期约束。稳定 ID 与项目级乐观锁让局部生产操作可以在并发编辑下明确处理冲突，JSONB 快照则适应不同生成模型的输入结构。

## 影响（Consequences）

### 正面影响

- 剧本与生产阶段边界清晰，漫剧菜单可以独立演进。
- 镜头、资产版本和媒体结果可按项目、集、场和状态高效查询。
- 上游变更不会丢失旧结果，用户可选择局部更新范围。
- 现有画布、分镜和 AI 生成服务可以作为执行引擎复用。

### 负面影响

- 需要维护生产表与共享剧本实体之间的稳定 ID 关联。
- 生成任务的外部状态与项目媒体结果需要异步同步或轮询。
- 画布 JSON 与正式镜头之间仍存在绑定同步责任。

### 风险

- 上游实体被删除或重排时，影响计算必须使用 ID 和来源快照，不能退化为名称匹配。
- 任何新增计费入口都必须继续沿用明确确认和报价流程。
- 生产表字段演进需要新增 Flyway 迁移，不能修改已发布版本。

## 后续行动（Action Items）

- 新增漫剧生产关系表和 `/comicDrama/*` WebFlux 接口。
- 在前端工作台实现准备度、设置、资产、镜头、提示词、媒体、画布和更新中心。
- 为剧本保存成功后的下游影响标记补充自动化测试和数据校验。
- 后续接入真实配音、连续性分析和团队协作时继续沿用稳定关联模型。
