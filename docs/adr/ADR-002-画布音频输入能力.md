# ADR-002: 画布音频输入能力

## 状态

Accepted

## 日期

2026-09-10

## 背景（Context）

画布需要承载上传音频，并将其作为视频生成参考。系统已有节点注册表、媒体存储、模型能力列表、视频生成模式、分档计费和渠道适配器。

## 问题（Problem）

音频输入是模型对参考素材的支持能力，不是一种独立的视频生成模式。能力是否开启应由管理员结合具体模型协议自行配置，服务端只校验该能力与视频模型及全能参考模式的基本关系。

## 决策（Decision）

- 新增独立音频节点，复用画布保存、媒体存储和节点操作；通过浏览器 Web Audio API 解码真实波形，播放状态不持久化。
- 使用现有模型 `capabilities` 中的 `audio-input` 标识音频输入，默认关闭。该能力不进入生成模式或分档价格列表。
- 管理员可以为任意视频模型配置音频输入，但必须同时开启全能参考；具体渠道适配器负责将音频引用转换为对应协议，未实现音频协议时在扣费前明确拒绝提交。
- 自定义模型沿用全能参考请求模板，并通过 `{{audioReferences}}` 占位符接收按引用顺序排列的音频 URL。
- 任务请求新增 `audioReferences`，复用媒体引用结构。音频必须先上传，服务端按存储记录校验归属、类型、大小和时长，在创建任务和扣费前拒绝不合法请求。
- 画布读取同一能力配置，模型或模式不匹配时保留素材并阻止提交，不自动丢弃音频或切换模型。

## 方案比较（Alternatives）

| 方案 | 评价 |
| --- | --- |
| 复用能力列表 | 已有配置下发链路，无需新增数据库字段；必须与生成模式校验分离。采用。 |
| 新增布尔数据库字段 | 重复现有能力表达方式，增加迁移和接口维护成本。不采用。 |
| 新增“音频生视频”模式 | 混淆输入能力和工作流，导致混合素材引用与计费维度膨胀。不采用。 |

## 原因（Rationale）

保留现有扩展点与业务边界，让能力配置、画布提示和服务端校验一致；渠道协议由原有适配器负责。

## 影响（Consequences）

### 正面影响

- 无需结构迁移，已配置模型默认行为不变。
- 节点与素材存储复用现有生命周期，音频引用可保存并重试。

### 负面影响

- 新增渠道需要在适配器中实现音频协议；管理员应仅为实际支持音频输入的模型开启该能力。
- 浏览器解码占用内存，上传限制为单文件 15 MB，解码结束立即释放上下文。

### 风险

- 供应商必须能够访问媒体地址，且可能有进一步内容限制；错误沿用现有任务失败反馈。
- 服务端校验使用媒体记录中的上传元数据，本次不引入服务端音频转码或探测链路。

## 后续行动（Action Items）

- 管理员为真实支持音频的模型启用开关。
- 按音频节点验收清单验证深浅主题、播放、导入导出和已实现渠道适配器的生成结果。
