# ADR-008: 故事知识库分析按模型与字数分档计费

## 状态

Accepted

## 日期

2026-09-27

## 背景（Context）

长篇小说分析会多次调用文本模型，成本随原文长度和模型不同而变化。现有文本模型只有按次的 `credit_cost`，不适合百万字级别的长任务。

## 问题（Problem）

- 需要在启动前给用户明确、可复核的积分报价。
- 长任务可能中断、重试、取消或最终失败，积分必须不多扣、不漏退。
- 价格和原文结构在报价后可能被修改。

## 决策（Decision）

- 管理员为**每个文本模型**维护有序、首尾相接、不重叠的字数档位（`story_bible_pricing.tiers`），不预置价格；缺少覆盖当前字数的档位时禁止启动。
- 计费字数为所选范围内**非空白 Unicode 码点数**：汉字、字母、数字、标点计入，空格、制表符、换行、全角空格不计入。
- `quoteAnalysis` 返回字数、档位、积分、原文修订与价格修订；`startAnalysis` 重新核算，任一不一致即要求重新报价。
- 使用客户端请求标识幂等创建任务，并在**同一数据库事务**中插入任务与预扣整笔积分（复用 `CreditService.chargeOperation`，操作标识为任务标识）。
- 可重试任务续跑不再扣费；最终失败或取消通过条件状态更新与 `refundOperation` 在同一事务中全额退款，状态更新失败则不退款，保证幂等。

## 方案比较（Alternatives）

### 按实际令牌数事后结算

更精确，但用户无法预知费用，失败时难以解释。

### 沿用按次价格

对长文严重低估成本。

### 按模型与字数分档预扣

报价可复核、实现简单，并能利用现有积分流水的幂等机制，因此采用。

## 原因（Rationale）

字数在导入后稳定、可由用户核对；档位让管理员按模型成本定价。预扣加条件退款避免任务中断时的积分不一致。

## 影响（Consequences）

### 正面影响

- 用户启动前即可看到确定积分。
- 重复提交、重复投递与重复取消都不会重复扣退。

### 负面影响

- 档位价格需要管理员按模型成本手动维护。

### 风险

- 价格设置过低会造成亏损；上线前需按真实长文验收结果校准档位。

## 后续行动（Action Items）

- 使用约 117.5 万计费字的样例小说验收后校准各模型档位。
