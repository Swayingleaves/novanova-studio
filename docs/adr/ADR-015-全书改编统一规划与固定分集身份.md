# ADR-015: 全书改编采用统一规划、固定分集身份与阶段计费

## 状态

Accepted

## 日期

2026-10-01

## 背景（Context）

ADR-013/014 建立的一键改编按事实条数分批，每批独立生成一整套故事概览、大纲与分集规划，再逐批合并并覆盖。分批边界与小说章节无关，模型每批都只看到全书的一小部分。

## 问题（Problem）

百万字作品会退化为极少的集数。实测一份 126 万字、已确认 1295 条事件与 32 条故事线的作品只产出 3 集，且三集标识分别为 `episode-1`、`ep-1`、`ep-plan-1` —— 说明它们是三次互不知情的独立生成被拼接而成。原因是三重的：

- 集数来自启动请求的 `settings.episodeCount`，项目默认值为 1，指令直接告诉模型“目标集数=1”。
- 分集规划本身被按 400 条事实切批，模型结构性无法规划全书集数。
- 分集落库是整表替换，之所以没有丢内容，只依赖“模型每批把已写入分集回带”这一隐式契约。

此外，模型被要求一次产出整套大纲与分集对象，条目多时只能靠多批轮流覆盖，人工修改与模型输出会互相踩踏。

## 决策（Decision）

- **分批只提炼剧情素材**。按原文偏移排序事件，故事时间、关系与故事线作为辅助信息，顺序不确定时明确标注；素材单元不写入正式大纲或分集。
- **分层汇总由容量驱动，而不是固定根数**。只要素材摘要放得下，就必须一次归纳全书策略：根汇总数量直接决定模型可划分的故事阶段上限，固定根数会把百万字作品压缩到极少数阶段。每个素材批摘要设上限，超出了才继续归并。
- **模型只建议集数，用户确认最终集数**。策略阶段给出主线、结局、集数理由、压缩取舍和各故事阶段建议集数；确认集数后由服务端按最大余数法分配配额，配额之和严格等于目标集数，且每个被保留的阶段至少一集。
- **服务端固定分集身份**。标识、集号与排序由服务端预先生成，模型只能填写这些分集的内容；集数、标识或覆盖范围不符合规划时拒绝保存，不通过追加分集或修改编号掩盖错误。
- **每条事件必须记录处理方式**。保留、合并或省略，合并指向对应分集，省略必须说明理由；同一事件被重复使用需显式标记为回顾。
- **新建 `novel_adaptation_workflows` 与 `novel_adaptation_units`**。前者保存不可变输入快照、实体映射、统一策略与固定分集；后者保存单元身份、输入边界、校验输出与预扣标识，成功输出是恢复与结算的唯一依据。
- **按阶段预扣，只结算成功单元**。素材与策略、统一规划、逐集正文分别预扣，预扣操作标识按阶段区分，避免共用同一标识被幂等判重而静默跳过扣费；失败或取消按未完成单元退款，续跑跳过成功单元，事实或项目修订变化时明确拒绝复用。
- **默认覆盖全书**，包含主线发展、人物成长与结局，不机械对应小说章节；允许合理省略支线，但必须展示取舍。
- **旧的分阶段改编链路弃用**，不再暴露生成入口，仅保留执行器用于服务升级前遗留任务；事实溯源、资产关联与一致性检查接口继续保留。

## 方案比较（Alternatives）

| 方案 | 优点 | 不采用或采用原因 |
| --- | --- | --- |
| 维持分批生成整套大纲与分集再合并 | 改动最小 | 不采用；每批各自产生“第一集”，集数与阶段粒度不可控，人工修改被分批覆盖 |
| 提高启动请求的集数上限并继续分批 | 实现简单 | 不采用；只会得到数倍于批数的重复集，剧情断裂且无法核对取舍 |
| 让模型直接输出全部分集标识与集号 | 服务端无需分配逻辑 | 不采用；模型可自行增删集数，无法在集数与阶段粒度上做硬校验 |
| 汇总树固定归并宽度 | 层级稳定 | 不采用；根数被压到个位数，故事阶段上限随之被锁死 |
| 按容量决定是否归并 + 服务端固定分集 | 阶段粒度与容量同时可控，身份不可被模型篡改 | 采用 |

## 原因（Rationale）

集数是产品决策，不是模型输出：由用户确认、服务端分配，才能在“保留足够故事阶段”和“控制总时长”之间取得确定结果。把模型输出限制在内容字段内，识别号与结构由服务端掌控，人工审阅与替换才有稳定基线。单元表让恢复、结算与审阅共用同一份持久化事实，不需要从进度计数反推。

## 影响（Consequences）

### 正面影响

- 故事阶段上限由全书素材容量决定，百万字作品可正常展开十余个阶段与数十集。
- 集数、集号与标识在生成前固定，模型无法悄悄增减集数。
- 事件取舍可逐条审阅，覆盖范围可核对，压缩是显式取舍而不是静默丢失。
- 三段计费与成功单元结算，取消、失败与续跑的账目一致。

### 负面影响

- 模型调用次数增加：素材按批归纳后仍需一次全书策略归纳，规划阶段也要按分集逐集细化。
- 需要维护两张新表与单元级恢复逻辑，任务状态机与旧流程并存一段时间。

### 风险

- 素材摘要的压缩比决定根汇总数量，摘要写得过长会触发不必要的归并、缩小阶段粒度；须在提示词与容量校验两侧共同约束。
- 策略阶段要求每个来源至少被引用一次，模型漏引用即整批失败，需要重新生成而不是静默降级。
- 替换旧分集与正文时可能影响下游漫剧内容，必须沿用“上游变更只登记影响、不修改下游数据”的既有规则。
- 阶段推进的幂等依据必须是本阶段单元是否已持久化，不能使用派生数据（例如已锁定的集数）：集数在规划之前就已写入，用它判断会让“只锁定了集数、尚未规划”的任务永久停在停点，且确认接口找不到任何可应用的草稿。

## 后续行动（Action Items）

- 按阶段补全统一规划与逐集正文的执行器，复用现有租约、停点与恢复机制。
- 回归用例覆盖：跨多批事实的百万字作品覆盖开头、中段与结局；确认 60 集恰好得到 60 个连续集号的固定分集；集数少于故事阶段数被拒绝；每条事件有取舍记录；中断与续跑不重复扣费。
- 旧链路整体下线后删除 `NovelAdaptationPlan`、旧执行器与对应用例。
