# ADR-006: 导入原文独立于剧本正式数据

## 状态

Accepted

## 日期

2026-09-26

## 背景（Context）

用户需要上传长篇小说或已有剧本，保存原文、章节和场景位置，并在后续生成改编剧本。现有 `script_*` 表存储可编辑的正式创作成果。

## 问题（Problem）

原著事实与改编内容的生命周期不同。若导入时直接写入正式剧本表，重新解析、人工校对和多次改编会覆盖创作成果，也无法稳定追溯原文。

## 决策（Decision）

- 在 PostgreSQL 中增加独立的导入原文、结构段、文本片段和导入任务表，通过项目标识关联现有剧本项目。
- 原文件存入现有私有腾讯云 COS 桶，只保存对象键，不向浏览器返回公开地址。
- 使用现有 Redis Stream 基础设施驱动导入任务，PostgreSQL 保存任务状态和检查点。
- 第一阶段不将导入结构自动写入人物、分集或正式剧本场次表。

## 方案比较（Alternatives）

### 直接写入现有剧本表

改动较少，但原文与改编混杂；重新解析和人工校对可能覆盖用户创作，原文位置也难以保持稳定。

### 使用独立图数据库保存原文结构

可进行复杂关系遍历，但章节、场景和连续文本的位置关系适合关系模型；额外数据库增加同步与运维成本。

### PostgreSQL 独立原文层

保留原文与正式剧本的清晰边界，并复用当前数据库、事务和权限模型，因此采用。

## 原因（Rationale）

原文不可变，校对只调整其结构投影；后续 AI 分析可引用稳定的位置和项目标识，避免双写与跨库一致性问题。

## 影响（Consequences）

### 正面影响

- 导入重试不会覆盖正式剧本。
- 原文可按位置检索并支持人工拆分、合并。
- 后续可将不同改编成果关联同一原文。

### 负面影响

- 需要维护原文结构与正式剧本之间的映射。
- 原文文本与文本片段存在少量重复存储。

### 风险

- 私有桶权限变化可能导致原文暴露；上传时必须校验匿名读取不可用。
- 长文解析需要限制文件与解压后文本大小。

## 后续行动（Action Items）

- 完成导入、可恢复任务及人工校对接口。
- 后续分析阶段添加证据与正式剧本的来源映射。
