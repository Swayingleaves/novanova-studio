# ADR-016: 3D 导演台原生集成与参考媒体导出

## 状态

Accepted。用户于 2026-10-11 确认需求与技术路线；功能尚未实现，运行能力尚未验证。

## 日期

2026-10-11

## 背景（Context）

画布已有图片、视频、分镜和视频合成节点，以及媒体存储、服务端工程保存、模型参考输入和 FFmpeg 任务机制。需要新增可编辑的 3D 导演台，制作构图、人物动作与运镜可控的图片和视频，作为生成视频的参考素材。

`storyai-3d-director-desk` 提供 MIT 许可的轻量人偶、姿势、机位和截图能力；`awplanet` 提供更完整的动态预演设计，但采用非商业许可，当前没有商业授权。两者均基于 React 18，本项目使用 React 19。

## 问题（Problem）

如何在不使用 iframe、不引入第二套任务和存储系统的前提下，把场景编辑、人物动画、镜头时间轴与稳定导出接入当前画布，并控制许可证、运行资源和维护成本。

## 决策（Decision）

1. 使用本项目同一份 React，原生集成按需加载的 3D 编辑器；一个导演台节点保存一个场景和一条时间轴，可以选择不同机位分别导出。
2. 以许可明确的 MIT 程序化人偶、姿势和机位能力为基础，自行实现确定性人物与摄像机轨道；只借鉴 awplanet 的能力划分，不移植未授权代码、界面或素材。
3. 画布节点保存工程 JSON 与稳定资产引用，复用现有服务端画布保存；节点只显示封面，编辑器打开时才启动 WebGL。
4. 使用同一个绝对时间求值器驱动预览、PNG 和视频采样。正式视频按固定时间步逐帧渲染并分批上传，由服务端 FFmpeg 编码为无音轨 MP4/H.264/yuv420p，首版 30 帧/秒、720p、2～15 秒。
5. 扩展现有视频任务类型 `directorDeskExport`，用 `preparing` 状态接收与封存帧，验证完整后转为 `pending` 并复用队列、进度、取消、超时、恢复与媒体登记。增加专门的帧序列编码分支，不调用多视频拼接入口。
6. 导出结果形成普通图片或视频节点及来源连线，复用现有模型引用能力；导演台工程不直接作为模型媒体输入。历史结果保持不可变，重新导出创建新结果。

## 方案比较（Alternatives）

| 方案                                     | 取舍                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| iframe 嵌入已有应用                      | 能隔离依赖，但用户明确排除；不采用                                                 |
| 合并两个完整项目                         | 包含未授权源码、重复状态与界面，且依赖版本不匹配；不采用                           |
| 浏览器实时录制再服务端转码               | 容器可统一，但无法修复采样掉帧与真实时间推进导致的动作差异；不作为正式导出         |
| 浏览器逐帧渲染并使用 WebCodecs 编码      | 可减少上传量，但增加编码与封装依赖及浏览器兼容性验证；首版不采用，也不作为自动兜底 |
| 服务端启动浏览器渲染场景                 | 可以脱离用户页面，但新增 GPU 或无头浏览器运行基础设施；首版不采用                  |
| 原生编辑、浏览器逐帧渲染、既有服务端编码 | 满足用户约束并复用任务基础设施；采用                                               |

## 原因（Rationale）

参考视频首先需要表达准确的运动时间与构图，编码格式统一并不能弥补实时采样的不确定性。绝对时间求值可同时用于跳播、截图和视频，减少预览与输出差异。

使用普通媒体节点承接结果可以让现有模型输入、下载和资产能力直接复用，也避免让生成服务理解 3D 工程。保留明确的工程修订快照可防止场景修改污染导出任务或历史结果。

## 影响（Consequences）

### 正面影响

- 原生界面与画布主题一致，不需要跨窗口通信与第二份 React。
- 图片与视频共享场景求值，工程可保存、复制与再次编辑。
- 服务端沿用既有任务和 FFmpeg 生命周期，不引入独立渲染集群。
- 通过许可明确的程序化人偶实现首版，不依赖 awplanet 商业授权。

### 负面影响

- 需要独立实现人物动作与机位时间轴，并扩展 GLB 资产恢复。
- 逐帧 PNG 上传增加带宽和临时存储成本，导出速度可能低于实时录制。
- 准备态仍依赖浏览器完成渲染，只有封存后编码能够由服务端独立执行。

### 风险

- React 19 与 3D 库版本、实际 FFmpeg/libx264 能力尚需技术验证。
- 上传背压、过期帧清理、重启恢复和幂等回填需要整体设计，不能只处理成功路径。
- 所选生成模型可能不支持参考视频或限制其时长、尺寸和格式，导出成功不代表输入一定合法。
- MIT 源码不等于所有附带模型可自由分发，第三方素材需单独管理许可。
