# ADR-003: 画布音频裁剪方案

## 状态

Accepted

## 日期

2026-09-12

## 背景（Context）

当前画布音频节点保存原始媒体地址、存储标识、真实时长和波形采样。Agnes、MiniMax 和 Evolink 的视频音频输入协议均以音频 URL 数组为输入，没有统一的开始时间、结束时间参数。项目服务端已经安装 FFmpeg，并由视频合成能力管理其可执行文件配置。

## 问题（Problem）

需要让用户在画布中选择音频片段，并保证播放预览、视频生成、任务保存、重试和引用去重使用同一段音频。方案还应保留原始素材，避免裁剪后影响其他节点或历史任务。

## 决策（Decision）

采用**非破坏性裁剪元数据与服务端按需生成派生音频**：

- 音频节点保存 `trimStartMilliseconds` 和 `trimEndMilliseconds`，原始媒体地址、波形和原始时长保持不变；未设置时表示完整音频。
- “裁剪”操作生成新的音频节点，并自动建立原节点到新节点的连线；原节点继续表示完整音频，新节点表示一个可独立引用的音频片段。
- 前端波形显示双端裁剪范围，播放时将播放位置限制在该范围内。裁剪范围随画布保存、复制、撤销重做和 ZIP 导入导出恢复，播放进度不持久化。
- 画布引用携带裁剪区间和有效时长；同一原始音频的不同裁剪区间视为不同引用，去重键必须包含原始存储标识与裁剪区间。
- 创建视频任务时，服务端校验裁剪区间位于原始音频范围内，再使用现有 FFmpeg 配置生成标准化音频派生文件，并登记到现有媒体存储。渠道适配器只接收派生文件 URL，因此 Agnes 的 `audios`、MiniMax 的 `audio_url` 和 Evolink 的 `audio_urls` 无需增加渠道分支。
- 派生文件按原始存储标识、裁剪区间和处理版本生成稳定缓存键；任务请求快照保存原始引用及裁剪区间，重试时复用或重新生成同一派生文件。
- 视频生成继续按有效时长执行每段 2～15 秒、总计不超过 15 秒的校验；普通节点播放只受原文件大小限制。

## 方案比较（Alternatives）

| 方案 | 评价 |
| --- | --- |
| 仅前端保存开始/结束时间 | 实现简单，但渠道仍会收到完整原音频，无法满足实际生成裁剪；不采用。 |
| 裁剪后覆盖原始文件 | 会破坏其他节点、历史任务和用户下载内容，撤销与恢复也更复杂；不采用。 |
| 各渠道分别传递裁剪参数 | Agnes、MiniMax、Evolink 没有统一参数，协议差异会扩散到任务和重试链路；不采用。 |
| 非破坏性元数据加服务端派生文件 | 保留原始素材，渠道协议统一，复用现有 FFmpeg 和媒体存储；采用。 |

## 原因（Rationale）

裁剪是对同一媒体的引用视图，不应改变原始资产。服务端生成派生文件可以让所有渠道收到真实一致的音频内容，也能在任务创建前完成时长和格式校验；稳定缓存键可避免重复转码和重复存储。

## 影响（Consequences）

### 正面影响

- 原始音频可恢复、复用和下载，节点操作符合非破坏性编辑预期。
- 播放预览与真实视频生成使用同一裁剪区间。
- 渠道适配器继续只处理 URL，不需要为每个渠道实现裁剪逻辑。

### 负面影响

- 需要扩展节点、引用、任务快照和导入导出数据结构。
- 首次生成或裁剪范围变化时会增加一次 FFmpeg 处理和派生媒体存储。

### 风险

- FFmpeg 进程需要超时、取消、临时文件清理和并发限制，避免资源泄漏。
- 派生文件缓存清理策略需要与任务重试和画布删除生命周期协调。
- 裁剪边界涉及毫秒精度，需统一取整规则，避免前端显示时长与服务端校验出现偏差。

## 后续行动（Action Items）

- 在 `ReferenceAudio` 和音频节点中增加裁剪区间字段，并更新复制、保存恢复、ZIP 导入导出和引用去重测试。
- 增加“裁剪为新音频节点”操作，沿用图片裁剪的节点创建、自动连线和选中新节点行为。
- 抽取可复用的服务端音频派生处理器，复用视频合成的 FFmpeg 路径配置和进程生命周期管理。
- 为裁剪范围、有效时长、派生缓存、任务重试和取消补充服务端测试。
- 完成实现后补充深浅主题下的波形双端拖动、键盘调整和真实渠道生成验收步骤。
