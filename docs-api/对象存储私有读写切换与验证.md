# 对象存储私有读写切换与验证（P3 执行手册）

> 适用：以腾讯云 COS 为主（阿里云 OSS / 七牛 Kodo 差异见 §7），配合《[对象存储私有读写改造方案](./对象存储私有读写改造方案.md)》P3 阶段执行。
> 目标：把默认桶从「公有读私有写」切到「私有读私有写」，并能在 10 分钟内确认成功或完成回滚。
> 前提：P0/P1 已完成，P2 前端续签已覆盖主链路（画布、图片/视频页、公开分享页）。P2 未完成就切桶，旧页面和历史 JSONB 数据会大量 403。

---

## 0. 一页流程

1. 选低峰期，确认线上版本包含 P0–P2 改造。
2. 审计历史对象 ACL（§1.2），把被单独设成 `public-read` 的对象改回 `private`。
3. 记录当前桶 ACL、`STORAGE_REQUIRE_PRIVATE_BUCKET` 取值、存储配置和 403 基线（§1.4），准备回滚。
4. 把桶 ACL 改为「私有读写」。
5. 确认桶已私有后，把 `STORAGE_REQUIRE_PRIVATE_BUCKET` 设为 `true` 并重启服务端。
6. 立刻跑 §3 验证清单的前 8 项，并盯 §6 指标 10 分钟。
7. 持续观察 24h：正常则 P3 完成，进入 P4 清理；异常按 §2.2 回滚（桶 ACL 改回公有读）。

---

## 1. 切换前检查（逐项通过才可切）

### 1.1 桶 ACL 准备（检查阶段只记录，不改）

- 控制台：COS → 存储桶 → 「权限管理」→「存储桶访问权限」，确认当前值并截图；切换动作在 §2.1 执行。
- coscli（`get` 用于记录，`put` 留到 §2.1 再执行）：

```bash
# 查询当前桶 ACL（先记录，回滚要用）
coscli bucket-acl --method get cos://<桶别名>
```

- 桶别名在 `coscli config add` 中配置（别名 → bucket + region）；直接用桶名时需额外携带 `--endpoint cos.<region>.myqcloud.com`。
- COS 桶 ACL 的 `READ` 表示「列出对象」（HeadBucket、ListMultipartUploads 等），切私有后匿名枚举也会被拒绝；对象能否下载取决于对象 ACL。

### 1.2 审计历史上被单独设为 public-read 的对象（关键，不通过不能切）

**对象 ACL 优先于桶 ACL。** 桶改成私有后，历史上被单独设过 `public-read` 的对象仍然可以被匿名下载；只改桶 ACL 会得到一个「假私有」桶。

检查方式：

1. **控制台文件列表**：抽查近期上传、分享副本、导出文件等重点前缀（`<目录>/images/`、`<目录>/videos/`、`shared-work/`、`script-source/`）。控制台逐对象查看只适合抽查，全量走下一步。
2. **coscli 单个对象查询**：

```bash
coscli object-acl --method get cos://<桶别名>/<对象键>
```

返回中出现匿名用户组 `http://cam.qcloud.com/groups/global/AllUsers` 且权限为 `READ`，即该对象可被匿名读取；预设 ACL 为 `public-read` 同样视为公开。

3. **SDK 批量扫描（推荐全量）**：
   - Java：`cosClient.getObjectAcl(bucket, key)`（本项目服务端已使用 COS Java SDK，`getBucketAcl` 也是同一套写法）。
   - Python：遍历 `client.list_objects(Bucket=..., Prefix=...)` 的 key，逐个 `client.get_object_acl(Bucket=..., Key=...)`。
   - 判断标准同上：grant 的被授权者是 AllUsers 组且 permission 含 `READ`。
   - 对象 ACL 为 `default` 表示继承桶权限，私有桶下无需处理。
   - 全量扫描前先导出待处理清单并核对数量，避免误改。
4. **修复**：

```bash
# 改成显式私有
coscli object-acl --method put --acl private cos://<桶别名>/<对象键>
```

也可以直接在控制台把对象 ACL 重置为「继承桶权限」；用 coscli 时统一改成 `private` 即可。批量脚本照第 3 步遍历执行；执行后复核匿名 HEAD/GET 应返回 403。

### 1.3 确认应用配置

- **签名/访问域名**（配置字段 `public_base_url`）：优先留空，COS 会使用 `https://{bucket}.cos.{region}.myqcloud.com`。如果填的是 CDN 域名，必须先完成 CDN 服务授权 + 回源鉴权，否则私有桶下 CDN 取不到数据；COS 预签名地址绑定 COS Host，不能把预签名 URL 的域名替换成 CDN 域名。
- **私有强制开关**：`STORAGE_REQUIRE_PRIVATE_BUCKET=false`（对应 `novanova.object-storage.require-private-bucket`）是切换前的兼容模式：检测到桶仍允许匿名读取时只记录告警并继续。切换完成后设为 `true`，此时小说原文导入、分享副本等私有内容在公开桶上会被拒绝。注意：`false` 时私有内容仍会写入公开桶，只留一条告警。
- **预签名 TTL**：确认四个 `STORAGE_SIGN_*` 环境变量能覆盖业务（长视频预览、大文件下载、第三方排队时长）；修改后需重启服务端生效。`docker-compose.yml` 已透传这 5 个变量并带默认值，未写入 `.env` 时使用默认值；改动后要重新创建服务容器（`docker compose up -d`），单纯 `restart` 不会重新注入环境变量。
- **服务端时钟**：开启 NTP 同步，签名有效期依赖本机时间。
- **桶 CORS**：允许站点域名 `GET/HEAD`（画布导出、`fetch(url).blob()` 需要）。
- **变更窗口**：不要与切桶同时升级前后端版本、切换 CDN 域名或清理数据，否则出问题无法定位。

### 1.4 备份与回滚准备

- 记录当前桶 ACL 输出（`coscli bucket-acl --method get`），截图或保存文件。
- 记录 `STORAGE_REQUIRE_PRIVATE_BUCKET` 当前取值（默认 `false`），回滚时一并考虑。
- 记录 `user_object_storage_configs` / `platform_object_storage_configs` 中的 `provider`、`bucket`、`region`、`public_base_url`（**不要导出密钥**）。
- 记录切换前 40 分钟的 COS 403 数量、接口 5xx、媒体加载失败基线，便于切换后对比。
- 确认回滚操作人和时间窗口；回滚动作是：桶 ACL 改回公有读，`STORAGE_REQUIRE_PRIVATE_BUCKET` 若已改成 `true` 则同步改回 `false`。

## 2. 切换步骤与回滚

### 2.1 切换步骤

1. 确认发布版本包含 P0–P2 改造，管理后台「测试上传」通过。
2. 把桶 ACL 改为「私有读写」（coscli 或控制台）。
3. 立刻在管理后台再点一次「测试上传」，确认：
   - 测试上传流程是「上传测试对象 → 尝试生成预签名地址并记录 GET 状态 → 匿名 HEAD 检查是否 403 → 删除测试对象」；探测失败只记告警日志，不阻断保存。
   - 服务端日志出现 `对象存储已拒绝匿名读取`；若出现 `对象存储仍允许匿名读取`，先停下来查对象 ACL 与桶 ACL。
   - 「打开测试文件」的预签名链接可以打开（若预签名失败，链接会回退为上传返回的地址，属预期）。
4. 确认桶已私有后，把 `STORAGE_REQUIRE_PRIVATE_BUCKET` 设为 `true` 并重启服务端，确认原文导入、分享副本不再降级到公开桶。
5. 按 §3 清单先跑前 8 项主链路，期间盯 §6 指标。
6. 无异常后持续观察 24h，记录切换时间、操作人、桶 ACL 前后值与开关取值。

### 2.2 回滚方式

```bash
# 改回公有读私有写
coscli bucket-acl --method put --acl public-read cos://<桶别名>
```

或控制台「权限管理 → 存储桶访问权限 → 公有读私有写」。

- 如果已经把 `STORAGE_REQUIRE_PRIVATE_BUCKET` 设为 `true`，回滚时同时改回 `false`（或删除该变量）并重启，否则桶恢复公开后原文导入、分享副本仍会被拒绝。
- 数据侧无需回滚：切换前后对象键不变，数据库里的 key 也不变，回滚后旧的公开 URL 立即恢复可读。
- 回滚后确认媒体加载恢复、COS 403 回落。
- 如果问题只出在 CDN 域名，先把「签名/访问域名」清空或改成直连桶域名，再判断是否需要回滚桶 ACL。
- 不要在回滚时顺便清理数据或改其他配置。

## 4. 常见故障

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 切换后大量旧图/旧视频 403，新上传正常 | 该读路径仍在使用数据库/JSONB 里的旧公开 URL（P2 未覆盖），或前端缓存了旧 URL | 先回滚桶 ACL；定位接口是否已签名，检查 `object_storage_url` 的残留读取与前端 `resolvedUrls` 缓存 |
| 个别对象 403 或匿名可读，同类对象正常 | 对象 ACL 覆盖桶 ACL：该对象被单独设过 ACL，权限与桶不一致（`public-read` 会继续允许匿名读） | `coscli object-acl --method get` 查 ACL，统一改回 `private` 或继承桶权限后复核 |
| 匿名仍能打开某些历史对象 | 对象 ACL 残留 `public-read`（安全风险，不是故障） | 批量改回 `private`，并用匿名 HEAD/GET 复核 403 |
| CDN 域名 403 / 502 / 回源失败 | CDN 未开服务授权或回源鉴权，或回源 Host/端口不对 | 开启 CDN 服务授权与回源鉴权；或把「签名/访问域名」留空、直连 COS 域名 |
| 403 `AccessDenied` / 签名过期 | TTL 太短、页面停留过久、任务排队超过有效期 | 调大对应 `STORAGE_SIGN_*`；确认前端到期或 onError 会重新取地址 |
| GET 正常、HEAD 403 | 预签名按 HTTP 方法生成，GET 签名不能用于 HEAD | 改用 GET（或 `Range: bytes=0-0`）；确实需要 HEAD 时单独签 |
| 浏览器打开变成下载 | 2024-01-01 之后创建的桶，默认域名强制 `Content-Disposition: attachment` | 绑定自定义源站域名，并保证签名地址 Host 与域名一致 |
| 分享页/日志/浏览器历史出现带 `q-signature` 的链接 | 签名 URL 泄露即临时凭据泄露 | 日志脱敏、分享页 `no-store`、缩短 TTL；不要把链接投放到站外 |
| 「测试上传」成功但日志提示 `对象存储预签名地址暂不可用` | 预签名 GET 失败：配置未保存、密钥/region 错误、桶或对象 ACL 不允许 | 检查存储配置与密钥、region；探测失败只告警、不阻断保存，但应尽快修复 |
| 小说原文导入/分享副本被拒绝，提示「当前默认对象存储桶允许匿名读取」或「不能保证分享副本私有」 | `STORAGE_REQUIRE_PRIVATE_BUCKET=true` 但桶或对象仍可匿名读取 | 按 §1.2 修完 ACL 后重试；临时可改回 `false`（不推荐长期保留） |
| 原文导入/分享副本成功，但服务端日志出现「私有内容保护已降级为告警模式」 | `STORAGE_REQUIRE_PRIVATE_BUCKET=false`，桶仍允许匿名读取，私有内容写进了公开桶 | 完成切桶后设为 `true` 并重启；把已写入的私有对象按 §1.2 审计 |
| 长视频播放中途失败 | 预览 TTL 短于实际观看时长 | 调大 `STORAGE_SIGN_PREVIEW_SECONDS` |

## 5. 不要做的事

- **不要批量把签名 URL 写回数据库/JSONB**：包括 `media_files.object_storage_url`、画布 `project_data`、`assets.asset_data`、生成记录 `result_data`、分享副本等。签名 URL 是临时凭据，落库即坏数据，TTL 一到全部失效。
- **不要把 CDN 鉴权和 COS 预签名混用**：COS 预签名绑定 COS Host，CDN 鉴权是另一套算法和密钥，不能拼接使用；本期若开 CDN，必须明确只走其中一套。
- **不要把永久密钥放到前端**：SecretId/SecretKey 只能保存在服务端，签名只在服务端做。
- **不要只改桶 ACL 就宣布完成**：跳过对象 ACL 审计会留下仍可匿名读取的历史对象，私有桶形同虚设。
- **不要在桶仍公开时就把 `STORAGE_REQUIRE_PRIVATE_BUCKET` 设为 `true`**：这会让小说原文导入、分享副本直接失败；也不要切完私有后长期保留 `false`，私有内容会继续写进公开桶。
- **不要在切桶窗口同时做其他变更**：域名切换、CDN 配置、版本升级、数据清理都会让故障难以归因。
- **不要给私有探针对象单独设置 ACL**：探针对象会继承桶权限才能反映桶级设置，单独设 `private` 会让公有桶也返回 403，校验结果失真。
- **不要把签名 URL 贴到工单、群聊、日志或公开仓库**，也不要用「复制链接」分享长期有效的媒体地址。

## 6. 观察指标与完成标准

- **观察指标**：COS 403 请求数与占比、Nginx/接口 5xx、前端媒体加载失败（Sentry/日志）、第三方生成任务失败率、分享页访问成功率、邮件图片发送失败、服务端日志中 `对象存储仍允许匿名读取` 与 `私有内容保护已降级为告警模式` 的告警数量。
- **完成标准**：
  - §3 验证清单全部通过；
  - 观察 24h 无新增 403、裂图、生成失败；
  - 对象 ACL 扫描无残留 `public-read`；
  - `STORAGE_REQUIRE_PRIVATE_BUCKET=true` 已生效（日志不再出现「私有内容保护已降级为告警模式」）；
  - 切换记录归档。
- **后续（P4）**：移除 `object_storage_url` 读取逻辑、`publicBaseUrl` 拼接、前端 URL 缓存字段、`SharedWorkCopyService` 落 300s 签名 URL；同步更新 `docs-api/backend-database.md`。`public_base_url` 列注释需按项目规范新增 Flyway 迁移修改，不要直接改已发布的迁移文件。

## 7. 其他服务商差异

- **阿里云 OSS**：适配器通过 `getBucketAcl` 判断是否 `Private`；同样要审计对象 ACL，对象级 `public-read` 会覆盖存储空间权限。
- **七牛云 Kodo**：私有桶必须通过已绑定的域名 + 签名访问，「签名/访问域名」不能留空；确认 CDN 或自定义域名已绑定。
- **Cloudflare R2**：不支持对象级 ACL，适配器会拒绝私有桶验证；不要把 R2 桶当作私有桶切换，保持公开桶或改用 COS/OSS/Kodo。
- 各服务商的 ACL 语义、匿名组标识和签名参数不同，按对应厂商文档执行，不要跨厂商套用命令。

## 8. 附录

### 8.1 coscli 速查

```bash
# 桶 ACL
coscli bucket-acl --method get cos://<桶别名>
coscli bucket-acl --method put --acl private cos://<桶别名>
coscli bucket-acl --method put --acl public-read cos://<桶别名>   # 回滚

# 对象 ACL
coscli object-acl --method get cos://<桶别名>/<对象键>
coscli object-acl --method put --acl private cos://<桶别名>/<对象键>
```

- 桶别名通过 `coscli config add` 配置；直接用 `<bucket-appid>` 时加 `--endpoint cos.<region>.myqcloud.com`。
- 查询对象 ACL 需要 CAM 权限 `cos:GetObjectACL`，修改需要 `cos:PutObjectACL`；查询/修改桶 ACL 需要 `cos:GetBucketACL` / `cos:PutBucketACL`。
