# 对象存储从「公有读私有写」切换为「私有读私有写」改造方案

> 适用版本：当前仓库（v1.x，腾讯云 COS / 阿里云 OSS / 七牛 Kodo / Cloudflare R2 适配器）
> 结论先行：改桶权限只需要 1 分钟，但系统现在把「公开 URL」当数据存进了 PostgreSQL、JSONB 和浏览器缓存，切私有后约有 6 类读路径直接 403。必须先把「URL 当数据」改成「存对象键、读时签名」。

## 1. 结论

1. **不能只改桶权限**。`media_files.object_storage_url` 是媒体地址的唯一权威来源，上传时写入公开 URL，之后从不刷新（`server/src/main/java/com/novanovastudio/service/PersistenceService.java:2087-2093`、`buildMediaRecord` `:2057-2078`）。桶切私有的那一刻，这张表里的所有 URL、以及复制进 `canvas_projects.project_data`、`assets.asset_data`、`ai_generation_tasks.result_data` 等 JSONB 的 URL 全部失效。
2. **真正的改造是"剥离 URL"**：写入只保存 `(storage_config_id, object_key)` 或业务 `storageKey`；读的时候由服务端**现签**预签名 URL（或 SDK 直读）；前端只把 URL 当短时展示态，按 `storageKey` 续签。
3. **公开运营资源与用户媒体应分流**：首页精选、风格/技能封面、社区二维码、团队 logo 这类非隐私资源放独立 public 桶或静态目录，避免全站所有图片都走签名，减少改造面。
4. **顺手修三个现存缺陷**：私有桶校验假阳性（`TencentCosObjectStorageProviderAdapter.java:143-170`）、分享复制把 300s 签名 URL 落库（`SharedWorkCopyService.java:125-127`）、前端 `resolvedUrls` 永久缓存（`web/src/features/storage/services/image-storage.ts:32`、`file-storage.ts:11`）。

## 2. 现状（代码事实）

### 2.1 写入即公开 URL

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 用户上传 | `PersistenceService#uploadMedia` `:1380` | 上传对象存储，拿到公开 URL，写入 `media_files.object_storage_url`，同时保留 `object_storage_key` |
| AI 生成（字节/文件） | `:1545`、`:1594` | 同上 |
| 音频裁剪派生 | `:1623` | 同上 |
| 远程转存 | `:1807`、`:1816-1838` | 同上；若已有 URL 直接返回，不会补签 |
| 分享副本 | `SharedWorkMediaService#copy` `:67-82` | 不落 URL，只存 `(storageId, objectKey)`（唯一正确的私有写法） |
| 复制分享画布到个人空间 | `SharedWorkCopyService` `:105-131` | 落库的是 300s 签名 URL（隐患） |
| 原文私密导入 | `ScriptSourceService#storeOriginal` `:389-407` | 只存 key，服务端 SDK 直读 |
| 云文件 | `storage_objects`（V60/V61） | 只存 `storage_id + object_key`，预览/下载现签（`StorageFileService.java:74-92`） |

`putObject` 的接口语义就是"返回公开访问地址"（`storage/ObjectStorageProviderAdapter.java:48-58`），COS 实现拼 `publicBaseUrl` 或桶域名（`TencentCosObjectStorageProviderAdapter.java:124-127`），并且 `PersistenceService` 强制校验 URL 非空（`:1985-2007`、`:2019-2025`）。**没有任何一处在上传后设置对象 ACL**，完全依赖桶默认权限。

### 2.2 读路径（四类访问者）

| 访问者 | 位置 | 现在怎么读 |
| --- | --- | --- |
| 浏览器 | `/media/uploadMedia`、`/media/getMediaInfo`、`/media/uploadRemoteMediaToObjectStorage`（`PersistenceController.java:357/386/413`） | 直接返回落库公开 URL；画布/素材/生成记录等接口直接透传 JSONB 里的 URL |
| 第三方模型厂商 | `AbstractTaskProfile.java:318-328` → 各 provider（OpenAI/Agnes/Evolink/MiniMax/Seedance/NewApi/Gemini/Custom） | 把 `media.url()` 原样写进请求体，由厂商来拉 |
| 本服务进程 | `AiHttpClient.downloadRemoteBinary/MediaToFile/streamRemoteMedia` `:531/561/606` | 视频合成（`PersistenceService:1687`）、分镜音轨（`:1713`）、下载（`:1764`）、导出视频（`:1793`）、音频裁剪（`AudioClipService:120`）、邮件图片（`EmailCampaignService` 调 `downloadMedia`） |
| 公开页 | `SharedWorkService#hydratedDetail` `:344-348`、`SharedWorkMediaService#access` `:113-119`；首页作品墙 `SharedWorkService:352-366` | 分享快照已有 `shared-asset:` 占位 + 现签 300s；**首页 official 条目直接返回 `homepage_showcases.media_url`** |

### 2.3 已经按私有读设计的链路（可复用为模板）

- 分享副本/分享详情：`SharedWorkMediaService#access`，每次现签 300s，`SharedWorkService.replace` 把快照里的占位键替换掉。
- 复制分享画布：`SharedCopyMediaAccessService`，只对 `storageKey` 含 `:shared-copy:` 的记录重签。
- 原文导入：`putPrivateObject` + `downloadPrivateObject`，不经 URL。
- 云文件：`StorageFileService#getFileAccess`，`preview/download` 分开签名。

### 2.4 已发现的隐患（与本次改造相关）

1. **私有桶校验假阳性**：COS 实现先上传一个显式 `CannedAccessControlList.Private` 的探针对象，再匿名 HEAD，`403` 就判私有（`TencentCosObjectStorageProviderAdapter.java:151-158`）。对象 ACL 优先级高于桶 ACL，所以**公有读桶也会返回 403**，这个校验实际没验证桶级权限。`ScriptSourceService:400`、`SharedWorkMediaService:52-57` 都信了它。
2. **校验成本/误判**：每次分享、每次导入原文都跑一次 PUT+HEAD+DELETE 探针；`publicBaseUrl` 指向 CDN 时，鉴权/CDN 缓存都会让结果偏 403。
3. **签名 URL 落库**：`SharedWorkCopyService:125-127` 把 300s 签名写进 `media_files.object_storage_url`，只有经过 `SharedCopyMediaAccessService.resolve` 的 7 个读路径会刷新。
4. **前端永久缓存**：`image-storage.ts:32`、`file-storage.ts:11` 的 `resolvedUrls` 无 TTL，一次解析整个会话复用。
5. **管理端"测试上传"**返回未签名 URL 并立刻删对象（`PersistenceService:1425-1441`），私有桶后"打开测试文件"必 403。
6. **日志脱敏不完整**：`HttpLoggingWebFilter:319-323`、`ApiAccessLogWebFilter:348-362` 只有在响应含 `expiresAt` 时才掩码 `url`；签名 URL 会把 `q-signature` 成批写进日志。

## 3. 改私有后直接失效的面（按优先级）

| # | 失效点 | 现象 | 依据 |
| --- | --- | --- | --- |
| 1 | 媒体接口返回落库 URL | 上传成功但预览/回显 403 | `PersistenceService:2087-2093` |
| 2 | 第三方模型拉参考图/视频 | 图生图、参考生视频、首尾帧全部失败 | `AbstractTaskProfile:318-328` |
| 3 | 服务端自己下载 | 视频合成、分镜导出、音频裁剪、导出下载、邮件图片 403 | `PersistenceService:1687/1713/1764/1793`、`AudioClipService:120` |
| 4 | 浏览器直接吃 JSONB URL | 画布历史节点、生成记录、素材、漫剧媒体、任务记录结果图全裂 | `canvas_projects.project_data`、`generation_logs.log_data`、`assets.asset_data`、`comic_drama_media_results.result_data` 等 |
| 5 | 只存 URL 的业务字段 | 头像、团队 logo、剧本/漫剧封面、提示词封面、风格/技能封面、社群二维码、首页精选 | 见 §4.2 |
| 6 | 管理后台测试上传 | "打开测试文件"403；连通性判断失真 | `PersistenceService:1425-1441` |

> 你现在的桶是「公有读私有写」：桶 ACL 的 READ 包含 `HeadBucket / GetBucketObjectVersions / ListMultipartUploads`（列出对象），对象 ACL 默认继承桶。也就是说匿名用户既能枚举对象、也能下载对象，风险比"URL 泄漏"更大。切私有后要同时检查**历史上被单独设成 public-read 的对象 ACL**——对象 ACL 优先，改桶不会覆盖它们。

## 4. 目标设计

### 4.1 总体原则

1. **对象存储里只认 key**：数据库和 JSONB 中不再把 URL 当唯一数据源。
2. **读地址一律服务端现签**：浏览器、第三方、本进程都走同一个签发入口；URL 不落库。
3. **短 TTL + 可续签**：按用途分级，前端在过期前或 403 时重新换取。
4. **公开与私密分流**：非隐私运营资源走 public 桶/静态目录；用户媒体走私有桶。

### 4.2 数据契约

| 数据 | 现在 | 改造后 |
| --- | --- | --- |
| `media_files` | `object_storage_url` + `object_storage_key` + `object_storage_config_id` | `object_storage_url` 不再作为读来源（可保留为历史/调试列并置空）；读只用 `object_storage_config_id + object_storage_key` |
| `canvas_projects.project_data` | 节点 `content.source/url/dataUrl`、`objectStorage.url`、`generation.references[]`、`videoReferences[]`、`audioReferences[].url`、分镜 `assets[].image.source`、导演台 `assets[]/cover` | 媒体节点必须带 `storageKey`（或 `objectStorage.key`）；URL 字段可以留作展示缓存，但**读取时以 key 重签结果覆盖**；新写入不再把签名 URL 当最终值 |
| `assets.asset_data` | 同上 + `coverUrl` | 主媒体保留 `storageKey`；`coverUrl` 改为 `coverStorageKey` 或去掉 |
| `generation_logs.log_data` / `ai_generation_tasks.result_data` / `video_composition_tasks.result_data` / `comic_drama_media_results.result_data` / `video_workflow_context.generated_images` | `items[].url`、`item.url`、`reference_images[].url` | 保留 `url` 仅作展示缓存，另存 `storageKey`（已有部分）；服务端返回前按 key 重签，任务历史"再次使用"改为按 storageKey 取 |
| 只存 URL 的列 | `users.avatar`、`teams.logo_url`、`script_projects.cover_url`、`skills.cover_url`、`generation_styles.cover_url`、`prompt_library.cover_url`、`platform_community_configs.image_url`、`homepage_showcases.media_url/thumbnail_url` | 二选一：① 新增 `*_storage_key` + `*_storage_id` 列，读时签名；② 这些资源只允许 public 桶/静态目录 URL（推荐给首页/风格/技能/社群/团队 logo） |
| `agent_session.messages` / `creation_agent_request.request_data` | 工具结果里带 URL | 续聊用不到就脱敏/去掉；需要回放时改存 storageKey |

> 按 AGENTS.md「项目尚未上线，不做旧数据兼容」的约定，本方案**不设计存量 URL 回填与双读兜底**；开发库里已有画布/素材数据在切换后失效属于预期，重新生成或重新上传即可。若你希望保住现有演示数据，再单列一个一次性脚本（见 §7）。

### 4.3 读地址签发

新增 `storage/MediaAccessService`（或扩展现有 `ObjectStorageService`）：

- `Mono<MediaAccess> sign(String storageKey)`：按业务键取 `media_files` → 校验归属 → 取存储配置 → 适配器 `createReadUrl`。
- `Mono<MediaAccess> sign(String storageConfigId, String objectKey, String fileName, String mimeType, Purpose purpose)`。
- `Mono<List<MediaAccess>> signBatch(List<String> storageKeys)`：列表/画布一次换取，避免 N+1。
- `record MediaAccess(String url, Instant expiresAt)`。
- TTL 分级（配置项，不要写死 300s）：
  - 页面预览/播放：30–60 分钟（长视频可 2 小时）
  - 下载：5 分钟
  - 第三方模型拉取：1–2 小时（覆盖异步任务排队）
  - 公开分享页：30 分钟 + 前端到期前自动换签
- **复用 COSClient**：现在每次签名 `new COSClient` 再 `shutdown`（`TencentCosObjectStorageProviderAdapter.java:72/82`），批量签名会放大开销；改成按 storageId 缓存 client，配置变更时失效。
- 适配器能力声明：`supportsPrivateAccess()`；R2 当前明确不支持私有对象（`CloudflareR2ObjectStorageProviderAdapter.java:112-116`），配置层拒绝或降级为"公开桶模式"。

### 4.4 服务端出口统一

1. **媒体接口**：`mediaResponse` 改为返回签名 URL，并在 `UploadedMediaResponse` 增加 `expiresAt`（同时能触发现有日志掩码）；`objectStorage.url` 也返回签名值。
2. **新增批量接口**：`POST /api/v1/media/batchAccess`（body: `storageKeys`），返回 `[{storageKey, url, expiresAt}]`，权限复用现有归属校验。
3. **JSONB 读时刷新**：在 `getProject`、`listGenerationLogs`、`listAssets`、漫剧媒体列表等返回前，对 JSON 中带 `storageKey`/`objectStorage.key` 的媒体对象重新签名并覆盖展示用 URL；不带 key 的历史数据不再兜底（见 §4.2 约定）。
4. **本服务进程下载**：把 `firstNonEmpty(record.getObjectStorageUrl(), record.getSourceUrl())` 换成 `downloadMediaToFile(record)`：有 `object_storage_config_id + key` 时优先 SDK `downloadPrivateObject`（`ObjectStorageService:88-90`），否则回退签名 URL 再 HTTP 下载。涉及 `PersistenceService:1687/1713/1764/1793`、`AudioClipService:120`、`EmailCampaignService` 图片快照。
5. **第三方参考素材**：`AiMediaSupport.resolveReferenceUrl:117-134` 与 `AbstractTaskProfile:318-328` 出口统一签长 TTL；能收二进制的渠道继续走 `resolveReferenceBinary:144-155`，减少外链。历史 `reference_urls` 只带 URL 的，改为按 `storageKey` 传（`extractMediaUrls:934-939` 产出的 `urls` 不要再当后续输入）。
6. **登录态媒体访问接口**：可选补齐 `GET /api/v1/media/access?storageKey=`（302 到签名 URL 或返回 JSON），给 `<img>` 直接引用提供无 JS 方案。

### 4.5 前端

1. **统一解析层**：新增 `useMediaUrl({ storageKey, url, expiresAt })` / `<MediaView>`，内部：
   - 命中带 `expiresAt` 的内存缓存且未过期 → 直接用；
   - 过期或 `onError` → 调 `getServerMediaInfo`/`batchAccess` 重签一次；
   - 同一 key 并发去重。
2. **缓存加 TTL**：`image-storage.ts:32`、`file-storage.ts:11` 的 `resolvedUrls` 改为 `{url, expiresAt}`；上传返回值带 `expiresAt`。
3. **渲染收敛**：约 60–70 处 `<img>/<video>/<audio>/antd Image` 需要接入统一层，优先顺序：画布节点 → 图片/视频生成 → 漫剧 → 素材库 → 首页/分享 → 后台。画布打开时的 hydration（`canvas-client-page.tsx:5950-6005`）已经按 key 重解析，保持并扩到 `objectStorage.url` 优先级之前。
4. **下载/导出全走 blob**：`media-download.ts:15-21` 已支持 storageKey；继续修 `asset-download.ts:10`（`saveAs(url)`）、`canvas-client-page.tsx:3132`、`media-download.ts:31-47` 的 URL 兜底、`canvas-client-page.tsx:5899/5904` 和 `reference-object-storage.ts:73` 的 `fetch(url)`、`image/page.tsx:1667-1670` 的 HEAD 探测。
5. **长期缓存改存 key**：`recent-reference-assets.ts`（localforage，只存 URL）、首页草稿 `homepage-creation-handoff.ts`、`canvas` 导出的 `canvas-documents.json`，统一改存 storageKey/相对路径。
6. **公开页续签**：分享页目前只有手动"刷新媒体授权"（`share/[shareCode]/page.tsx:41`），`/sharedWork/getMediaAccess` 前端零引用；改为进入页面取一次、到期前自动换签；首页作品墙用批量接口。
7. **复制链接功能**：`video/page.tsx:2528`（复制来源 URL）、`video/page.tsx:2532`（复制云存储 URL）、`result-detail-dialog.tsx:166` 复制的都是永久地址，私有后要么改成"复制临时链接（提示有效期）"，要么去掉。
8. **不再把 URL 写回服务端**：画布/素材自动保存时剔除 `objectStorage.url`、`generation.references[].url` 等展示字段，或服务端保存时统一清洗。

### 4.6 公开资源分流

- 推荐：首页精选、风格封面、技能封面、社群二维码、团队 logo、平台品牌图 → 放 **public 桶或 web 静态目录**，继续用永久 URL；`homepage_showcases.media_url` 只允许公网静态地址（管理端上传走静态发布流程）。
- 用户可见但需长期稳定地址的（头像、剧本封面）：仍走私有桶 + 签名，列表接口签名；若发现频繁刷新成本高，可给这两类做 public 前缀（`avatars/public/...`）并明确"公开头像"的产品语义。

### 4.7 存储配置与管理后台

1. `public_base_url` 语义从"素材公网访问前缀"改为"签名访问域名（可空）"；若填 CDN 域名，必须清楚 COS 预签名绑 Host，**CDN 域名上不能直接用 COS 预签名 URL**（需 CDN 鉴权 TypeA/TypeD 或改直连桶域名/自定义源站域名）。
2. 新增"访问模式"配置（private/public）或直接全局私有；R2 只支持 public，配置层提示。
3. **校验改造**：
   - "测试上传"改为：上传 → 签名 GET 200 → 匿名 HEAD 应 403 → 删除；
   - `verifyPrivateBucket` 改为读桶 ACL（SDK `getBucketAcl`，确认无 `AllUsers` READ）或匿名探测**继承 ACL 的对象**（不要给探针对象单独设 Private），并把结果缓存在配置上，配置变更/保存时重验；
   - 返回值带 `expiresAt`，让前端"打开测试文件"用签名链接。
4. 签名 TTL、是否启用签名改为配置项（`NOVANOVA_STORAGE_SIGN_TTL_*` 或平台配置表），不要散落硬编码。

### 4.8 运维

1. 桶 ACL 改 `private`；桶策略拒绝匿名读写；检查并重置历史对象 ACL（曾被设为 public-read 的对象在私有桶里仍可匿名读）；关闭"公共读"相关的防盗链依赖。
2. 若继续用 CDN：必须开「CDN 服务授权 + 回源鉴权」，否则私有桶下 CDN 完全取不到数据；要真正受控还需开 CDN 鉴权（TypeD）并由应用实现 CDN 签名——**推荐本期不上 CDN，媒体直连 COS/自定义源站域名**。
3. 2024-01-01 后创建的桶，**COS 默认域名不能浏览器预览/直链下载**（会带 `Content-Disposition: attachment`），需要绑定自定义源站域名；签名 URL 的 Host 与域名必须一致。
4. 桶 CORS：允许站点域名 `GET/HEAD`（画布导出、`fetch(url).blob()`、图片转 dataURL 需要跨域）。
5. 日志：对 `q-signature`、`X-Amz-Signature`、`sign`、`t` 等参数以及任何含 `expiresAt` 的 URL 统一掩码。
6. 时钟同步（NTP），签名有效期依赖本地时钟。

## 7. 风险与坑

1. **签名过期**：COS 预签名过期后请求中断，不支持断点续传；长视频要 1–2h TTL，并在播放器出错时换 URL。前端必须有 `onError` 重签。
2. **GET 签名不能用于 HEAD**：签名串包含 HTTP 方法；需要 HEAD 时单独签，或前端用 `GET Range: bytes=0-0`。
3. **缓存命中率**：每次请求重新签名 → URL 变化 → 浏览器/CDN 缓存失效。缓解：同一 `expiresAt` 窗口内签出相同 URL（按整点取整）、前端内存缓存、批量接口。
4. **CDN 两套签名**：COS 预签名绑 COS Host；CDN 域名要用 CDN 鉴权（TypeA/TypeD）。二者不能混用，配置 `publicBaseUrl` 时必须明确。
5. **默认域名限制**：2024 后新桶默认域名不支持浏览器预览，需自定义源站域名。
6. **对象 ACL 覆盖桶 ACL**：切桶后必须审计历史对象 ACL；否则"桶已私有"是假象。
7. **日志/分享泄漏签名**：签名 URL 即凭据，TTL 内任何人可用；日志脱敏、分享页 no-store、不要把签名 URL 投稿到站外。
8. **公开页抓取**：社交平台/微信抓取分享卡片时不会带登录态；当前分享页是客户端渲染、无 OG 图，问题不大；若以后做 SEO/社交卡片，需为封面提供公开静态地址。
9. **外部链接型字段**：管理端允许手填外链（风格封面、首页精选等），切私有后这些字段要么保持外链（不受影响），要么改成本站桶的 key；不能既存本站 URL 又期望长期有效。
10. **R2/七牛差异**：R2 无对象级 ACL、明确拒绝私有；七牛签名方式不同；按 provider 能力分流，不要假设所有 provider 都支持私有读。

## 9. 备选方案

### 方案 A：私有桶 + CDN「源站保护」（改代码最少，但不是真私有）
桶私有 + CDN 服务授权 + 回源鉴权（不开 CDN 鉴权），应用把 `publicBaseUrl` 配成 CDN 域名。
- 效果：COS 源站域名匿名访问 403、无法枚举桶；但通过 CDN 域名，任何拿到 URL 的人仍可匿名读取，等价于"半公开"，且 CDN 缓存可被恶意拉取。
- 代码：几乎不用改，只需把存量 URL 的域名批量替换为 CDN 域名（DB/JSONB 全量 UPDATE），新数据走 `publicBaseUrl`。
- 结论：只适合"消除桶被枚举/盗刷"，不满足"私有读"的实质；如果目标只是降风险，这是最省事的止血方案，但别把它当最终态。

### 方案 B：私有桶 + CDN 鉴权（TypeD）
真正受控，但应用要实现 CDN 签名（与 COS 预签名两套密钥）、配置缓存键"全部忽略参数"、维护两套 TTL。适合大视频 CDN 加速场景，建议作为 P3 之后的独立阶段。

### 方案 C：服务端反向代理
`/api/v1/media/{storageKey}` 服务端鉴权后流式转发，URL 永久、天然鉴权。缺点：带宽/内存压在服务端，视频 Range/高并发成本高，不适合作为主渲染方案，可作为下载/私有文件兜底。

**推荐路线**：方案（私有桶 + 预签名直连 COS/自定义源站域名）+ 公开运营资源分流；CDN 只在确有加速需求时按方案 B 单开。
